# 2026-08-10 工作日志

## 数据同步 BUG 排查与修复（deploy/index.html + sw.js）

### 核心 BUG（严重）：非隔离模式下 sha 永远为 null → 422 同步失败
- **位置**：`ghPullAll()` 第 2693 行（原 2690 行）
- **原因**：sha 记录条件 `if (f === myFile) mySha = r.sha` 在非隔离模式（没填"我的同步文件"，个人空间默认）下 `myFile` 为空字符串，`f`（=`'情绪记录.json'`）永远不匹配 `''`，导致 `mySha` 永远为 `null`
- **后果**：推送时 `ghPush(payload, null, file)` 不带 sha，GitHub 对已存在的文件返回 422 "sha wasn't supplied"；422 重试 3 次仍拿不到 sha → 全部失败 → 用户看到"同步出现冲突"
- **影响范围**：所有个人空间用户（默认不填"我的同步文件"）+ 共享空间不填该字段的用户
- **修复**：`if (f === (myFile || GH_FILE)) mySha = r.sha;` — 非隔离模式下 `myFile || GH_FILE` 退化为 `GH_FILE`，正确匹配

### 次要改进：推送 404 友好提示
- **位置**：`ghSync` catch 块（第 2978-2983 行）
- **原因**：推送 404（仓库不存在）走通用错误处理，只显示"同步失败：推送失败 HTTP 404 — Not Found"
- **修复**：增加专门的 404 分支，提示"仓库 xxx 不存在或令牌没有权限。请在 GitHub 先建好这个私有仓库"
